# 需求覆盖与验收边界

当前贡献入口采用[严格双审和双人工审批](strict-dual-review.md)。以下旧版验证记录不构成新版回执。模拟采集器的签名仅验证协议和阻断行为，不证明发生过真实模型调用或人工批准。

本表区分“代码已实现且有离线验证”“还需真实环境联调”和“明确未承诺的能力”。本次没有制造任何实际开源成果，示例也不能进入正式台账。

## 1. 分阶段覆盖

| 需求 | 当前实现 | 验收边界 |
|---|---|---|
| Stage A 检查现有项目 | 确认只有需求附件；独立建立项目 | 没有旧源码或 schema，无法证明旧项目向后兼容 |
| 发现与去重 | GitHub 搜索、配置领域权重、仓库规范化与去重 | 真实 REST 传输未在本次环境打通；采集数量不是硬性完成指标 |
| License / 活跃度筛选 | 缺许可证保持待检查；不活跃、归档、Fork、自有仓库有明确原因 | 许可证 allowlist 是参与筛选配置，不代替法律分析 |
| Maintainer Intelligence | 有界 PR/Issue 样本、响应时间、合并率、证据链接与身份门槛 | 非完整历史统计；Review 质量为可解释代理指标，缺证据为 UNKNOWN |
| 仓库评分 | 六维带证据评分、未知项、可见分值区间 | 不把未知项按零分包装成“不欢迎贡献” |
| Clone / Worktree | 原始 clone、单 Finding 分支、独立验证与实施空间 | 本地 Git fixture 验证；真实 clone/push 需目标环境联调 |
| Slimming / Manifest | 原路径、原字节、行号、哈希、排除原因与增量复用 | 秘密识别是启发式；不能保证过滤所有凭证 |
| Mapping / Chunking | Python AST 分块、imports/符号和 TOML 依赖清单、其他语言行区间回退 | 没有完整跨语言调用图、类型推断或程序语义证明 |
| 多 Provider | OpenAI Responses、兼容 Chat、Anthropic Messages、Gemini generateContent 独立适配 | Mocked API 验证；没有真实付费调用，也不预置未经验证的模型 ID |
| 多角色审查 | 主审、独立审查、反方、汇总、最终 Diff 建议，可配置角色映射 | 模型结果只能是候选或建议，不能自行批准 |
| Token / 成本 / 缓存 | 完整请求缓存、Prompt 版本、并发、预算预留、用量和未知费用记录 | Token 为本地保守估算；价格需用户配置；本地预算不是供应商强制账单上限 |
| Finding | 最多五个候选、源码位置校验、候选去重、拒绝伪造下游状态 | 无候选只代表已完成范围内未形成可靠候选，不是全仓无 Bug |
| CC 独立验证 | 当前上游 preflight、查重、针对性材料、结构化报告、CLI 桥接和声明式外部导入 | 本次没有安装可用 CC，未执行真实 CC 会话；不能声称 AI 自动证明程序正确 |
| 复现与实现 | 经检查命令实际运行、基线失败、修复后同命令通过、源码/日志完整性校验 | 环境错误不能冒充 Bug 复现；缺依赖须记录 BLOCKED/失败 |
| 双重人工批准 | 实施范围批准、最终公开草稿批准；摘要、到期与单次消费 | 本机批准人字段是操作者声明，不是远程身份认证系统 |
| GitHub 写入 | 正确上游/Fork/用户身份核对，批准后推送和创建；Outbox 与只读恢复 | 没有自动 Merge 或自动回复；不确定写入不会被盲目重发 |
| Review 闭环 | 状态、评论、Review、CI 快照与修订待办；修订回到批准/实现/测试 | 维护者没有回复时程序只能保持等待，不能保证合并 |
| Issue 接受 | 已获取的维护者评论 + 可信身份 + 用户明确确认 | CLOSED、completed 或礼貌措辞单独不能计为接受 |
| Portfolio | 真正外部上游、正式接受证据、同一 Finding 去重、撤销与历史保留 | 不是 Activity 统计器；本地数据库不是第三方公证 |
| Profile 草稿/发布 | 先确认真实仓库，保留贡献区块外的原文，Diff 与独立批准 | 初始没有真实成果；绝不假定 Profile 仓库存在 |

## 2. 自动化测试关注的失效模式

测试不需要 API Key，覆盖能够破坏贡献证明或造成误提交的关键边界：

| 风险 | 对应测试范围 |
|---|---|
| 请求重复、凭证使用错误 | GitHub 读写授权、真实用户身份读取、条件缓存、分页、限流、跨域阻断、模糊写入不重试 |
| 选错项目或过度解释数据 | 去重、低 Stars 活跃项目、许可证、活跃度、自有仓库、未知维护者与不完整评分 |
| 模型输入污染或输出夸大 | Symlink/秘密排除、CRLF 与行号、bundle 完整性、Provider 独立 payload、结构校验、候选状态限制 |
| 成本失控或恢复重复请求 | 输入/输出预算、供应商 usage 缺失、已成功请求缓存、部分批次和重试边界 |
| 本地数据被并发覆盖 | CAS 版本冲突、事务回滚、事件禁止修改/删除、Outbox 摘要冲突 |
| 批准覆盖了不同内容 | 审批摘要、过期、已消费、草稿/HEAD/测试证据变化 |
| 伪造复现和测试通过 | 真实子进程、失败与 PASS 区分、日志篡改、基线源码修改、测试期间源码或 HEAD 改变 |
| 证据遗漏特殊文件 | 未追踪测试、合法前导空格路径及源码树哈希 |
| 执行泄露运行者凭证 | 精简子进程环境、记录参数和日志脱敏、主机执行显式选择 |
| 项目之间互相污染 | 独立 Worktree、原仓库保持不变、上游新 SHA 保留旧验证材料 |
| 误认上游接受 | Fork/自有仓库、错误作者、旧 Review、未合并关闭、自己的合并、Issue 错误采纳、评论修改/删除 |
| Profile 夸大或损坏原文 | demo/imported 不入账、同一 Finding 合并去重、重复 marker 拒绝、保留原文和换行 |

最终测试数量与命令以交付说明的本次运行结果为准，避免文档中的固定数字随着补充回归过期。全套命令：

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

## 3. 上线前仍需完成的真实联调

1. 在用户机器上验证只读 GitHub 搜索、clone 和真实 Review 快照；当前执行环境的 REST 传输失败不能代替这一项。
2. 选择一个账户确实支持的模型 ID，以小预算验证响应与 usage；没有进行过付费调用。
3. 安装兼容 Claude Code CLI，先验证结构化输出和工具禁用配置，再处理一个真实候选。
4. 为目标项目准备可重复的隔离测试环境，确认基线失败及修复后通过。
5. 对具体 Fork、公开 PR/Issue 和 Profile Diff 逐项人工批准，再验证真实写入及状态回读。
6. 在真实维护者 Review、修订与接受之后，检查台账和 README 引用的上游证据。

这六项是外部连接与真实贡献事实的验收，不应通过假数据、改状态或扩大审批范围替代。

## 4. 本版本未包含

- 完整的 Rust/TypeScript 等语言语义分析、跨仓库调用图或自动证明 Bug 真实性。
- 对所有秘密格式的完整识别、对恶意外部代码的绝对隔离保证。
- 无人批准的大规模公开提交、自动联系维护者、自动合并。
- 服务商的服务器 Batch API、所有模型的精确 tokenizer、全部缓存计费规则。
- GitHub Enterprise 全域名证据校验、多机器共享数据库、旧 Repo Scout 自动迁移器。
- 已经发生的真实合并贡献或已经吸引到的合作机会；这些需要实际后续工程工作和上游决定。

接口事实以 [GitHub 官方参考](api-github.md) 和 [模型官方参考](api-models.md) 中的来源为依据；运营时还应根据所用账户、模型与平台更新核对。
